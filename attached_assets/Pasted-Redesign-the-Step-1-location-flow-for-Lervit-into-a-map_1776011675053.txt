Redesign the Step 1 location flow for Lervit into a map-first mobile experience with a dedicated address-entry screen, and fix the booking map camera/rendering logic so route previews always frame correctly.

Primary goal:
Increase map height and improve UX by removing the full pickup/dropoff form from directly under the map. Replace it with a compact single entry/summarized location card. When tapped, it should open a dedicated Pickup & dropoff input screen. After the user confirms both addresses, return to the main map screen with the route rendered properly and the compact summary shown underneath.

This redesign must also fix the current map rendering issue where the route sometimes appears in a broken or awkward camera fit (for example, narrow vertical corridor framing, edge-biased route fit, or missing clear endpoint presentation).

1. Main booking map screen
- Keep the header
- Increase map height significantly so the map becomes the primary surface
- Use a tall mobile map, roughly 55–62vh if it fits cleanly
- Under the map, show only one compact location card instead of the full stacked pickup/dropoff form

Initial state of the compact card:
- Show a placeholder such as:
  - “Enter pickup & dropoff”
  - or “Where is your move?”
- Tapping the card opens the dedicated address-entry screen

Confirmed state of the compact card:
- Show short pickup and dropoff summaries
- Include a clear edit affordance
- Keep the card compact and clean
- Do not expand back into the full form on the main screen

2. Dedicated Pickup & dropoff screen
- Open as a focused full-screen or sheet-style mobile screen
- Include:
  - close/back control
  - title: “Pickup & dropoff”
  - pickup input
  - dropoff input
  - location permission/current location status
  - autocomplete suggestions / recent locations if available
- Optimize this screen for typing, keyboard behavior, and address selection
- Make sure autocomplete results are stable and easy to tap

3. Return behavior
- Once pickup and dropoff are confirmed, return to the main map screen
- Render the route only after both addresses are verified
- Update the compact summary card with the selected addresses
- Ensure the map camera fits the full trip cleanly

4. Route rendering logic
- Do not allow incomplete input states to produce broken map fits
- Only render and fit the route after final verified pickup/dropoff coordinates are available
- Ensure both endpoints and the full route are visible with balanced padding
- Avoid awkward corridor or edge-biased map framing
- Preserve a premium route preview feel on mobile

5. UX goals
- The main booking screen should feel map-led, premium, and spacious
- The input screen should feel focused and efficient
- The address-entry workflow should be separated from the map display workflow
- The result should feel closer to an Uber-style location-entry pattern adapted for Lervit’s moving use case
- The route preview should be the visual hero after addresses are set

6. Keep the design polished
- Preserve Lervit’s dark premium visual language
- Keep the main screen uncluttered
- Reduce vertical crowding from forms on the map screen
- Make the route preview the visual hero after addresses are set
- Ensure the compact summary card looks clean and readable
- Keep interactions smooth and app-like

7. Acceptance criteria
- The main screen uses a taller map with a compact location card underneath
- Tapping the card opens a dedicated Pickup & dropoff screen
- Confirming addresses returns to the main map screen
- The route renders only after addresses are fully confirmed
- The route camera fit is clean, centered, and balanced
- No more narrow vertical or edge-biased route render
- Pickup and dropoff are both clearly visible
- The main screen feels cleaner and more premium than the current stacked-form layout
- The full trip is readable at a glance
- The booking map behaves like a polished logistics route preview, not a broken auto-fit implementation
