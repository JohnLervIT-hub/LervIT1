## 1. Implement "scroll to top on navigation"

Goal: Whenever the user navigates to a new page/route, the main scroll position should reset to the top, so users never land mid-page.

### If using React Router:

1. Create a component `ScrollToTop.tsx` (or similar) in a suitable folder, e.g. `src/components/layout/ScrollToTop.tsx`:

   - Use `useLocation` and `useEffect`:
     - On every `location.pathname` change, call `window.scrollTo({ top: 0, left: 0, behavior: 'auto' })`.

2. Wrap the main route tree with this component:

   - In the file where the router is rendered (usually `App.tsx` or similar), render:

     <ScrollToTop>
       {/* existing <Routes> / layout */}
     </ScrollToTop>

   - Ensure this doesn’t break existing layout.

### If using Next.js:

1. In the main layout or custom `_app.tsx`, use `useRouter` from `next/router`.

2. Add an effect that subscribes to `router.events.on('routeChangeComplete')` and calls `window.scrollTo({ top: 0, left: 0, behavior: 'auto' })`.

3. Clean up the event listener in the effect’s cleanup function.

### If a scrollable container is used instead of window:

- If you find a main scroll container (like `<div id="app-scroll">`), reset that container’s `scrollTop = 0` instead of `window.scrollTo`.

Test:
- Navigate through the booking flow on mobile and ensure every new screen starts at the top.

## 2. Preload the Payment page when on Load Details step

### 2.2 Prefetch data via TanStack Query

1. Identify the query key and function used to fetch data for the Payment/Review step:
   - For example, `useQuery(['pricingSummary', bookingId], ...)` or similar.
   - Or any query that fetches fare breakdown / final price.

2. In the Load Details step:
   - Use `queryClient.prefetchQuery(...)` to prefetch the same query(s) used by the Payment page.
   - Only prefetch once the required input (location, vehicle, etc.) is available so the query key is valid.

Example pattern (pseudo-code, adapt to real names):

3. Ensure prefetching is non-blocking:
