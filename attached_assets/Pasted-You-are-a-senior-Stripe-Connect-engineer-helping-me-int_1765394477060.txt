You are a senior Stripe Connect engineer helping me integrate LIVE Stripe payments into my Uber-style moving marketplace called **Lervit**, running on Replit.

CONTEXT
- Lervit connects **customers (buyers)** with **movers/drivers (sellers)**.
- Customers pay Lervit; Lervit takes a platform fee and then pays the mover.
- Each job has ONE assigned mover.
- Movers are independent contractors and will have **Stripe Connect Express** accounts.
- Currency: **CAD**.
- Business is based in **Canada (Alberta)**.
- We have already created a LIVE Stripe account and enabled Connect with:
  - Flow: **Buyers → Your Platform → Sellers**
  - Payouts: **Sellers paid out individually**
  - Onboarding: **Hosted by Stripe**
  - Account management: **Express Dashboard**.

TECH STACK
- This Replit project uses a Node.js backend (Express) with TypeScript.
- Frontend is a web app that can call REST APIs on the backend.
- We are now moving from test mode to LIVE mode.

YOUR TASK
Design and implement a clean, production-ready Stripe Connect integration for Lervit in LIVE mode. Please:

1. GENERAL SETUP
   - Install and configure the official `stripe` Node.js SDK.
   - Use environment variables only (NO hard-coded keys):
     - `STRIPE_SECRET` → live secret key (sk_live…)
     - `STRIPE_PUBLISHABLE` → live publishable key (pk_live…)
     - `STRIPE_WEBHOOK_SECRET` → webhook signing secret for the live endpoint.
   - Create a small `config/stripe.ts` helper that exports a preconfigured Stripe client.

2. MOVER (SELLER) ONBOARDING – STRIPE CONNECT EXPRESS
   - Create an API endpoint, e.g. `POST /api/stripe/create-onboarding-link`.
   - Input: authenticated mover ID from our database.
   - Behavior:
     - If the mover does not yet have a `stripeAccountId`, create a new **Express** connected account for them (type: `custom: false`, `express: true`) with country CA and payouts enabled.
     - Save the connected account ID in our `movers` table (e.g. `stripe_account_id` column).
     - Create a Stripe **AccountLink** for hosted onboarding:
       - `type: "account_onboarding"`
       - `refresh_url`: our frontend URL to restart onboarding (e.g. https://app.lervit.com/mover/onboarding/refresh)
       - `return_url`: our frontend URL on success (e.g. https://app.lervit.com/mover/onboarding/success)
     - Return the `url` from the AccountLink to the frontend so we can redirect the mover into Stripe’s onboarding flow.
   - Also create an endpoint `GET /api/stripe/create-login-link` that returns a Stripe Express login link for onboarded movers to manage payouts, banking info, etc.

3. CUSTOMER PAYMENT FLOW (BOOKING A JOB)
   - For now, assume each booking has:
     - `bookingId`
     - `customerId`
     - `moverId`
     - `totalPrice` in CAD cents
     - `platformFee` in CAD cents (what Lervit earns)
   - Create an endpoint, e.g. `POST /api/stripe/create-payment-intent` or `create-checkout-session`:
     - Input: `bookingId`, `amount`, `moverId`, and `customerId`.
     - Validate that:
       - Booking exists and belongs to this customer.
       - Booking has an assigned mover.
       - Mover has a `stripe_account_id` and is fully onboarded.
     - Create a PaymentIntent in **LIVE** mode with:
       - `amount`: total job price in cents
       - `currency`: `cad`
       - `automatic_payment_methods: {enabled: true}`
       - **Connect transfer**:
         - Either using: 
           - application_fee_amount = platformFee
           - transfer_data[connected_account] = mover’s `stripe_account_id`
         - Or: create a separate `transfer` after payment succeeds.
       - Attach metadata: `bookingId`, `customerId`, `moverId`, `vehicleClass`, etc.
     - Return `client_secret` (if using Payment Element) or a Checkout URL (if using Checkout) to the frontend.

   - Document in comments which flow you implement:
     A) Directly with `transfer_data` + `application_fee_amount`, OR
     B) PaymentIntent → on success, create separate `transfer`.

   - Use best practices:
     - Idempotency keys for booking-related operations.
     - Proper error handling and logging.

4. WEBHOOKS (CRITICAL)
   - Create an Express route `POST /api/stripe/webhook` that:
     - Reads the raw request body (configure Express middleware correctly so raw body is available).
     - Verifies the signature using `STRIPE_WEBHOOK_SECRET`.
   - Handle at least these events:
     - `payment_intent.succeeded`
       - Mark the booking as paid in our database.
       - If using post-payment transfers, create a `transfer` to the mover’s connected account with the right amount.
     - `payment_intent.payment_failed`
       - Mark booking as payment_failed.
     - `charge.refunded` (future)
       - Mark booking as refunded and adjust driver payout/transfer if needed.
     - `account.updated`
       - Update our mover record when Stripe marks the connected account as charges_enabled / payouts_enabled.
   - Log all events safely for debugging (no secrets).

5. BASIC BOOKING/PAYOUT LOGIC
