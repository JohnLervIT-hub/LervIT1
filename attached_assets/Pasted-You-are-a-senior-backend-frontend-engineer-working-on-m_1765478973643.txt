2. Fix: No retry on transient API failures
----------------------------------------------------------------------

Goal: For **transient** network errors or 5xx responses, add a limited, safe retry mechanism.

1. Identify the main HTTP client layer or TanStack Query fetch functions.

2. Implement a small **retry utility**, for example:

   - Retries only for:
     - Network errors (e.g., fetch failed, ECONNRESET).

   - Uses **limited retries** (e.g., max 2–3 attempts).
   - Uses simple incremental or exponential backoff (e.g., 300ms, 600ms, 1200ms).
   - Never retries:
     - 4xx errors (validation issues, auth issues).
     - Idempotent rules: only apply to GET/HEAD and safe operations, not to charge/withdraw actions.

   - Do **not** wrap Stripe charge or booking commit calls in automatic retries unless they’re already idempotent and use idempotency keys.
